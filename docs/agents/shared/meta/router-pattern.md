# The Router Pattern

**Deep meta-rule.** Describes how the rule system itself is
organized in every consuming repo. Changes here ripple across
every consumer.

## The pattern

Every consuming repo has **one entry point** — by convention an
`AGENTS.md` at the repo root — that an AI agent reads first.
That entry point is a router, not a rule dump. It does three
things:

1. **Carries the universal session rules** that apply to every
   session in the repo (pre-edit gate, scope guardrails,
   stop-and-report, sub-agent delegation, anti-patterns,
   change boundaries). These come from this library.
2. **Routes by session type to per-session-type playbooks**.
   A short table that says "if your session is X, read these
   files." Implementation sessions, debugging sessions,
   review-fix sessions, UI-review sessions all have their own
   playbook.
3. **Names the constraint sets to load at the right session
   moment.** Topic-organized constraint files (architecture
   guardrails, validation surface, doc-currency triggers,
   PR-shape schema) live separately and are loaded when the
   workflow file points at them — not as optional lookups,
   but as binding reads at named session moments (pre-edit
   gate, per-commit, end-of-session).

The split matters: the entry point stays short and routable.
The detailed rules live in modules. A new agent reading the
entry point gets a one-page mental model of the rule system,
not a 7,000-line wall of text.

## Why this is a deep meta-rule

Most rules in this library are *content* rules — they tell an
agent what to do. The router pattern is *structural*: it tells
the consuming repo how to organize its own rule system.
Changing the router pattern changes how every consumer's
agent-rule surface is shaped.

## Design rationale for the starter skeleton

The starter `AGENTS.md` template in `starter/AGENTS.md` is the
concrete embodiment of the router pattern. It ships with:

- A "Repo orientation" placeholder where the consumer fills
  in what's in the repo.
- A "Development workflow source of truth" placeholder where
  the consumer names its contributor-workflow doc.
- The pre-loaded universal-session-rules section that links to
  this library's `core/` modules.
- A session-type routing table that ships with rows for the
  common session types and is meant to be edited (rows
  deleted if not applicable, rows added if the repo has
  novel session types).
- A "Mandatory pre-edit reads" placeholder where the
  consumer lists mandatory pre-edit reads in the three-component form (Intent / Triggers / Read).
- A "Self-review" section pointing at the catalog
  mechanism in this library and the consumer's local
  catalog.
- An "Adding to this rule set" section pointing at
  `meta/rule-additions.md`.

The starter is rough by design: filling it in should be a
10-minute task, not a writing exercise. See `starter/AGENTS.md`
in this repo for the template content.

## What this rule does not say

This rule does not prescribe a specific filename
(`AGENTS.md` is a convention used by current popular agent
tooling, but another filename would work) or a specific
directory layout for the per-session and per-topic files. It
prescribes the *pattern*: one entry point, routes by session
type, constraints loaded at session-moment.
