# Anti-Patterns

Patterns to avoid unless the task explicitly requires them. The
anti-patterns audit-flagged in source material as a flat
laundry list of eight items is here regrouped by organizing
principle. The flat list fired inconsistently in practice; the
regrouped form gives each principle its own load-bearing sentence
and concrete don'ts.

## Don't defer validation

Validation is part of the change, not a final polish pass.

- Deferring all validation until the final step of a long change.
  Multi-step work that only meets a test runner at the end has
  already accumulated drift; the drift is just invisible until then.
- Letting tests lag behind renamed, moved, or restructured code.
  The first commit of a rename should keep tests aligned, not
  promise to update them later.
- Using a final commit to clean up drift that should have been
  caught in earlier self-review. The "drift cleanup" commit is a
  symptom that self-review didn't happen at commit boundaries.

See [`../validation/philosophy.md`](../validation/philosophy.md)
"Continuous Validation" for the positive form.

## Don't let supporting artifacts drift

Tests, docs, ownership notes, and module headers are part of the
diff, not paperwork attached to it.

- Undocumented module splits, file moves, or ownership changes.
  When responsibilities shift, the doc that named the old
  responsibility split is now stale; updating it is part of the
  same change.
- Stale comments and stale durable docs left in place because the
  code changed but the prose didn't.

See [`../doc-currency/currency.md`](../doc-currency/currency.md)
for the doc-side discipline.

## Don't bundle unrelated cleanup

A focused diff stays focused.

- Combining unrelated cleanup with the requested change. The
  cleanup may be defensible on its own merits, but bundling it
  with the requested change makes the review surface harder to
  reason about and obscures what actually shipped.
- Large one-shot refactors with no written plan or intermediate
  checkpoints. The "I'll just clean this up while I'm in here"
  pattern lands as one giant diff that no one can review honestly.
- Treating a prompt as permission to skip the repo workflow.
  Workflow steps that get skipped silently are the ones the next
  agent gets blamed for.

See [`scope-and-stop.md`](scope-and-stop.md) for the named-target
boundary rule and [`change-boundaries.md`](change-boundaries.md)
for the targeted-fix discipline.

## Don't name durable artifacts after the rollout cycle that produced them

Durable artifacts are named by what they are, not by the rollout
cycle that produced them.

A living test or code file named after the phase, release, or
milestone that birthed it carries a fossil reference forward
forever. Name by the feature or surface under test so the filename
still makes sense after the phase ships.[^phase-name-example]

[^phase-name-example]: In the source codebase this rule came
    from, the concrete trap was test files named `foo_phase3_bar.test.sql`
    that outlived "phase 3" by months and had to be renamed to
    `event_code_data_model.test.sql` / `redemption_data_model.test.sql`
    once the phase reference was meaningless. Consumers can replace
    this footnote with their own incident.
