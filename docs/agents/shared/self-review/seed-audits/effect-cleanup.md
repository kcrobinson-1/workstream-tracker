# Effect Cleanup Audit

**Trigger.** A diff adds or modifies an effect that subscribes to
an event, opens a connection, schedules a timer, installs a
listener, registers a callback, acquires a resource, or otherwise
sets up state that the surrounding lifecycle is supposed to tear
down on exit.

**Check.** For every such effect in the diff, walk the component
or function on every exit path (unmount, error, early return,
re-render with a changed key, cancellation) and confirm a
matching cleanup runs:

1. Locate the setup site (`addEventListener`, `subscribe`,
   `setInterval`, `setTimeout`, an `open(...)` of any
   resource, `useEffect` body, etc.).
2. Locate the corresponding teardown. For React effects, the
   returned cleanup function. For other shapes, the explicit
   `removeEventListener` / `unsubscribe` / `clearInterval` /
   `clearTimeout` / `close` call paired on the same logical
   exit path.
3. Confirm the teardown runs on *every* exit, including error
   paths and conditional setup.
4. Confirm the teardown closes over the same reference the
   setup created (a common bug: subscribing with one function
   reference and unsubscribing with a recreated one).
5. If the setup is gated by a flag or condition, confirm the
   teardown is gated the same way.

**Example (illustrative).** A `useEffect` in a modal component
subscribes to a global keydown listener to handle Escape but
never returns a cleanup function. Closing the modal leaves the
listener attached; the next modal instance adds a second
listener; Escape now fires the closed modal's handler. The fix
is the missing cleanup return. Consumers can replace this
example with a real incident their codebase has hit.
