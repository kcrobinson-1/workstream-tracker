# Validation Honesty Audit

**Trigger.** A diff claims that a validation check, a test, a
workflow step, a baseline command, or a deployment gate ran —
in a commit body, a PR description, a status block, a handoff
note, or a self-reported review summary.

**Check.** For every such claim, verify the check actually ran
end-to-end:

1. The named command ran on the current branch state (not a
   stale state from before later edits).
2. The check produced output the agent actually read, not just
   a green tick assumed because the command exited zero.
3. If the check covers a "real" backend, browser, or
   production-shape path, confirm the run actually exercised
   that path rather than a fallback or mocked mode.
4. If the check is a newly added validation surface, it ran
   end-to-end at least once on this branch, not just in
   isolation.
5. Anything that *could not* be run is named explicitly with
   the reason, not silently omitted from the Validation
   section.

The trap this audit blocks: an agent writes "ran the lint
check" because earlier in the session lint passed, but a later
commit introduced a syntax error and the lint check was never
rerun. The claim is true in spirit, false in fact, and the
honest version is "ran lint at commit X; not rerun since."

**Example (illustrative).** A PR body checks "ran the e2e
suite," but the actual local run used a fallback flag that
skipped the real backend path the e2e suite is supposed to
exercise. The check passed because nothing was tested. The fix
is either to rerun the suite without the fallback flag and
report honestly, or to label the run as fallback-only in the
Validation section. Consumers can replace this example.
